CONTEXTO
═══════════════════════════════════════════════════════════

El incidente del perfil Linux (desaparición de ~/.local/share/uv)
ha cambiado el enfoque del proyecto. Ya no se trata solo de tener
un agente potente (Hermes), sino de construir un laboratorio
reproducible para estudiar, comparar y mejorar agentes de IA.

Joko Lab se organiza en 4 pilares:
  1. Knowledge    → modelos, experimentos, benchmarks, prompt compiler
  2. Infrastructure → docker, servicios, recovery, inicio/fin
  3. Automation  → scripts, cron, workflows, tests
  4. Operations  → informes, métricas, incidencias, changelog

═══════════════════════════════════════════════════════════
REGLAS DE LA ESTRUCTURA
═══════════════════════════════════════════════════════════

1. ~/joko-lab/ es la raíz única. Todo el conocimiento del
   laboratorio vive aquí.

2. ~/hermes-lab/ sigue siendo el repo de Hermes. No se toca.
   Solo se referencian o enlazan componentes que pertenecen
   al laboratorio.

3. Los números (01-, 02-) no son prioridad, son orden lógico.
   Knowledge va primero porque los otros pilares dependen de él.

4. Cada ficha de modelo es un archivo .md autocontenido con
   frontmatter YAML para que sea parseable por máquina.

5. inicio/ y fin/ son directorios, no scripts sueltos. Cada
   check es un script independiente y comprobable.

6. Los informes van a 04-operations/reports/ fechados. No más
   ~/informes-joko-lab/ suelto.

═══════════════════════════════════════════════════════════
NOTAS ADICIONALES
═══════════════════════════════════════════════════════════

- La Prompt Factory / Prompt Compiler no es una skill aislada.
  Es un subsistema central de Joko Lab del que todo depende.

- inicio y fin no son scripts de conveniencia. Son el equivalente
  a las operaciones de apertura y cierre de una transacción.

- El ciclo de mejora continua:
  Joko Lab → estudia modelos → aprende → mejora Prompt Compiler
  → Prompt Compiler mejora Hermes → mejores experimentos
  → el laboratorio aprende más → vuelve a mejorar

- Este diseño está alineado con los principios LPA (JL-011, JL-012)
  y con la arquitectura de AI Router de Joko Lab.

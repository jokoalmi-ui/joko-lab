# Registro de decisiones

## 2026-07-05

### Mejora continua

**Contexto**

El laboratorio crece con el tiempo: se añaden servicios, skills, documentación y automatizaciones. Sin una revisión periódica, pueden acumularse redundancias, documentación desactualizada y oportunidades de mejora sin aprovechar.

**Problema**

Necesitamos que Hermes Agent, al trabajar sobre Joko Lab, mantenga el laboratorio ordenado y en evolución constante, no solo ejecute tareas puntuales.

**Alternativas consideradas**

(pendiente)

**Decisión adoptada**

Cuando Hermes Agent trabaje sobre hermes-lab, deberá de forma sistemática:

- Detectar redundancias
- Detectar documentación obsoleta
- Proponer nuevas Skills
- Proponer reorganizaciones
- Sugerir automatizaciones
- Auditar periódicamente el laboratorio

**Motivos**

- Mantener la documentación y estructura del laboratorio siempre actualizada
- Evitar duplicación de esfuerzos y configuración
- Aprovechar el potencial de Hermes Agent para auto-mejora del propio laboratorio
- Que el laboratorio evolucione de forma orgánica y no por acumulación

**Procedimiento**

Durante cualquier conversación:

- Detectar redundancias.
- Detectar documentación obsoleta.
- Detectar decisiones sin registrar.
- Detectar skills que deberían dividirse.
- Detectar información repetida.

No modificar nada automáticamente.

Presentar siempre las mejoras ordenadas por:

- Impacto
- Esfuerzo
- Riesgo

Esperar confirmación antes de realizar cambios.

**Consecuencias**

- Cada interacción sobre hermes-lab incluirá una revisión ligera del estado actual
- Se registrarán propuestas de mejora en decisiones o issues
- El laboratorio se auditará periódicamente de forma automática o semiautomática

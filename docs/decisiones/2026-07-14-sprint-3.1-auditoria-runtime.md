# Sprint 3.1 — Auditoría del Runtime de Joko Lab

**Fecha:** 2026-07-14
**Estado:** Activa. Refleja el estado real del laboratorio tras la auditoría técnica.

---

## Contexto

El Sprint 3.0 (2026-07-14) planificó la consolidación del Runtime Agéntico.
Este documento registra la auditoría técnica completa de los componentes
existentes, realizada antes de cualquier modificación.

Todos los datos provienen de comandos ejecutados en la sesión del 14 julio 2026.
Las referencias a línea exacta y salidas de terminal están documentadas en
`docs/runtime/runtime-audit.md`.

---

## Problema detectado

La arquitectura actual tiene un Runtime funcional pero con:

1. Acoplamiento a config.yaml a través de `apply-decision.sh`.
2. Un cron que decide periódicamente en lugar de bajo demanda.
3. Un bug en el State Manager (SECRETS_DIR placeholder).
4. Logs duplicados.
5. Cero tests automatizados.
6. Documentación inconsistente con la realidad.
7. Siete scripts muertos en disco.
8. Dos fuentes de verdad sin jerarquía documentada.

## Decisiones

1. **El Runtime debe ser el único punto de decisión.** Queda prohibido que
   cualquier script externo (cron, apply-decision.sh, etc.) decida el proveedor.
2. **El contrato del Runtime (`runtime/CONTRACT.md`) es vinculante.** Cualquier
   implementación nueva debe cumplirlo.
3. **No se implementará nada nuevo hasta consolidar.** Los bugs existentes
   (SECRETS_DIR, logs duplicados) se corregirán, pero no se añadirán
   funcionalidades.
4. **Los scripts muertos se eliminarán.** No se archivan, se borran.
5. **La documentación se sincronizará con la realidad.** No puede haber
   `docs/estado-real.md` diciendo algo distinto a lo que `state.json` muestra.

---

## Alternativas consideradas

1. **Dejar los scripts muertos como "por si acaso".** Rechazado: generan
   confusión y no aportan valor.
2. **Reescribir el Decision Engine desde cero.** Rechazado: el DE es funcional
   y puro. Solo necesita desacoplarse de apply-decision.sh.
3. **Añadir tests primero.** Rechazado: el contrato debe existir antes que los
   tests (Contract-First).

---

## Consecuencias

- El laboratorio pasa a tener una única fuente de verdad documentada (state.json
  → ultima-decision.json → defaults).
- La documentación queda sincronizada con la realidad del sistema.
- La deuda técnica queda identificada y priorizada (9 ítems en la auditoría).
- El camino para eliminar el provider global está trazado.

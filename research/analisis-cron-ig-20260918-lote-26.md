### Los 4 tipos de agent loops (18-sep 08:05) — `dailydoseofds_` (DdZFC8WjLVi)

> The four types of agent loops, explained visually 🔁
> >
> > Loop engineering is often talked about as one thing, but there are actually four structures, each suited to a different kind of task.
> >
> > At the core, every agent loop answers two questions:
> >
> > ➡️ What starts the run?
> ➡️ What decides the work is done?
> >
> > In a hand-run session, the human answers both. Each loop type moves more of that responsibility into the system.
> >
> > Here are the four types:
> >
> > 1️⃣ Turn-based loops
> >
> > Triggered by a user prompt.
> >
> > The agent gathers context, acts, checks its work, and returns the output. A human reviews it and writes the next prompt.
> >
> > Use this when the requirements are still evolving and each result affects what should happen next.
> >
> > 2️⃣ Goal-based loops
> >
> > Triggered by a goal with success criteria and a budget.
> >
> > Example: “Get the homepage Lighthouse score to 90. Stop after 5 tries.”
> >
> > When the agent wants to stop, an evaluator checks whether the goal has actually been met. If not, it goes back to work.
> >
> > Use this when the outcome is measurable but the path does not need constant human attention.
> >
> > 3️⃣ Time-based loops
> >
> > Triggered by a clock.
> >
> > At a fixed interval, the agent runs a predefined task such as “check the PR and fix CI,” then waits for the next tick.
> >
> > Use this for recurring work where the task stays the same and only the timing repeats.
> >
> > 4️⃣ Proactive loops
> >
> > Triggered by an event or schedule, with no human present.
> >
> > A routine detects something that needs attention and launches the required workflow: triage, fixing, reviewing, and closing the task.
> >
> > Use this for standing responsibilities where you cannot predict what will happen, only that something eventually will.
> >
> > The progression is simple:
> >
> > ➡️ Turn-based: human triggers + checks
> ➡️ Goal-based: system checks
> ➡️ Time-based: system triggers
> ➡️ Proactive: system handles both
> >
> > So the question isn’t which loop is the most advanced.
> >
> > It’s whether your task is exploratory, measurable, recurring, or standing.
> >
> > 👉 Which type are you using most today?
> >
> > #aiagents #loopengineering #anthropic".

### RLM / context rot — MIT (18-sep 08:30) — `dailydoseofds_` (Dday5m1D6bj)

> Researchers from MIT solved AI's biggest problem 🧠
> >
> > a clever, forward-compatible solution
> >
> > You paste a 200-page document into ChatGPT. You ask a simple question. The answer comes back wrong, even though the information is right there on page 50.
> >
> > This is called "context rot." Even when the context fits in the model's window, performance drops. The model loses its ability to recall and reason over information. You didn't exceed the limit. The model just got worse because there was too much to process at once.
> >
> > The fix they proposed is called Recursive Language Models.
> >
> > Here's how they work:
> >
> > In a normal LLM call, you send the query and full context together. The model processes everything at once.
> >
> > In an RLM, the context is stored separately as a variable in a Python REPL environment. The model never sees all of it directly.
> >
> > Instead, it gets access to tools that let it:
> >
> > → Peek at portions of the context (like the first 2000 characters)
> → Grep through it using regex or keywords
> → Partition it into smaller chunks
> → Call itself recursively on those chunks
> >
> > Each recursive call works like a function call in programming. It gets a smaller piece of the problem, solves it, and returns the result to the parent.
> >
> > Concrete example:
> >
> > You have 5,000 customer support tickets and ask: "Among users 12345, 67890, and 11111, how many questions are about billing?"
> >
> > Normal LLM: Receives all 5,000 tickets, gets overwhelmed, makes counting errors.
> >
> > RLM does:
> 1️⃣ Peek at first few entries to understand structure
> 2️⃣ Run regex filter for target user IDs (50 lines instead of 5,000)
> 3️⃣ Spawn recursive sub-call: "Classify each as billing or other"
> 4️⃣ Count billing ones and return answer
> >
> > The key insight: Traditional LLMs treat context as a black box to process all at once. RLMs treat context as data to be programmatically explored.
> >
> > Forward compatible and improves as foundation models get better.
> >
> > Paper and starter code in the comments!
> >
> > 👉 Over to you: Have you experienced context rot in your LLM workflows?
> >
> > #llm #mit #airesearch".

### 4.3 dailydoseofds_ — RLM / context rot (MIT) `Dday5m1D6bj` → ⭐ FUENTE PRIMARIA + FUTURIBLE CON SEÑAL
**Ya conocido:** el análisis de Prime Agent (16-ago, `analisis-prime-agent-vs-hermes-rodolfocarrasco.md`) describía la arquitectura RLM (contexto como variable en un REPL de Python + subagentes recursivos). Este post aporta **el origen y los números**.
**Datos verificados (fuente y fecha):**
- Paper: *Recursive Language Models* — arXiv **2512.24601v1** (dic-2025) + blog del autor `alexzhang13.github.io/blog/2025/rlm/` (consultados 18-sep-2026).
- Divulgación con cifras: VentureBeat, **20-ene-2026** («MIT's new 'recursive' framework lets LLMs process 10 million tokens without context rot»).
- En OOLONG `trec_coarse` con **132k tokens** de contexto: `RLM(GPT-5-mini)` supera a `GPT-5` en **>34 puntos (~114 %)** con coste por query similar; a **263k tokens**, +15 puntos (~49 %). Ablacionar la recursión cuesta ~10 %. Todo el contexto cabía en la ventana de GPT-5: la pérdida **no** era truncamiento, era *context rot*.
- Mecanismo: el modelo no ve el contexto entero; en su lugar recibe herramientas para **peek / partition / transform / map** sobre él vía código, y hace sub-consultas.
**Barrido de duplicados (hecho):** no hay ningún `research/` con «RLM»/«recursive» en el nombre; el backlog no tenía entrada de RLM (0 coincidencias de «recursive language»/«context rot»).

Encaja con el pitfall del lab «el contexto no garantiza que se cumplan las reglas» y con los 43.951 fragmentos del RAG. Requiere experimento propio con modelo local antes de creer nada.

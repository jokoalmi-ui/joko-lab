1. What You're Building
Your agent calls one LLM API. The API returns a 429, or a 503 "model is experiencing high demand", and your agent dies halfway through its job. On free tiers this isn't rare: Gemini's free tier returns 503s on busy days.
You'll build the fix every production team ends up writing: one complete(messages) call with three providers behind it. Gemini goes first, Groq is the fallback, and a small model on your own laptop is the last resort.
A support agent triages six tickets in one run. You'll knock providers out mid-run and watch the router retry, give up, switch, stop calling the dead one, and later test whether it's back. The customer-facing replies look the same throughout.
You'll learn four ideas by building each one: provider abstraction, retry with backoff, circuit breakers and graceful degradation. At the end you'll rebuild the same thing with LiteLLM and see what a library gives you and what it hides.

2. Architecture Overview
[Diagram showing flow from "Support agent" → "LLM router" → "Gemini primary" (fails) → "Groq fallback" (fails) → "Ollama on your laptop" (fails) → "Holding reply and human flag" → "Customer reply"]
The agent only ever talks to the router. The router walks the providers in order. Each provider gets its own retries and its own circuit breaker.
A provider "fails" when its retries run out, or when the error isn't worth retrying at all, like a bad API key. Then the router moves to the next one. If all three are down, the customer gets an honest holding message and the ticket gets flagged for a human. The run never crashes.

5. One Error Type for Three SDKs
Here's the first real problem. Gemini raises google.genai.errors.ClientError with a .code. Groq raises groq.RateLimitError with a .status_code. Ollama raises ollama.ResponseError, or a plain Python ConnectionError when the app isn't running.

If the router had to know all of that, adding a fourth provider would mean editing the router. So every exception gets translated into one ProviderError that answers the only question the router cares about: is it worth trying again?

Start with the type and the retry rule. Save as src/errors.py :

"""
One error type for every provider, so the router never imports an SDK.

Inputs: any exception raised by google-genai, groq, ollama or the network.
Outputs: ProviderError with `retryable` and an optional `retry_after` (seconds).
"""

import groq
import httpx
import ollama
from google.genai import errors as genai_errors

# Status codes worth trying again: rate limits, timeouts and server-side troubl e.
# Everything else (400 bad request, 401 bad key, 404 wrong model) fails the same # way every time, so retrying only burns the clock.
RETRYABLE_STATUS = {408, 429, 500, 502, 503, 504}

class ProviderError(Exception):
    """A provider call failed. `retryable` decides retry vs. instant failove r."""
    
    def __init__(self, provider: str, reason: str, status: int | None,
                 retryable: bool, retry_after: float | None = None) -> None:
        super().__init__(f"{provider}: {reason}")
        self.provider = provider
        self.reason = reason # short label for logs: "429" or "ConnectionError (...)"
        self.status = status
        self.retryable = retryable
        self.retry_after = retry_after

The split between retryable and fatal is the most important decision in the whole project. A 429 means "slow down", so trying again later can work. A 401 means "this key is wrong". Retrying a 401 three times just makes the customer wait three times longer for the same failure.

    s."""

    details, dict) else []

            return float(str(item.get("retryDelay", "0s")).rstrip("s") or 0)
    return None

def _header_retry_after(headers: httpx.Headers) -> float | None:
    """Read a numeric Retry-After header, the way Groq sends it on a 429."""
    value = headers.get("retry-after")
    try:
        return float(value) if value else None
    except ValueError:
        return None

Now the translation itself. Each SDK gets one isinstance branch that pulls out the status code. Anything with no status code is either a network failure (worth retrying) or a bug in our own code (not worth retrying).

def _status_and_wait(exc: Exception) -> tuple[int | None, float | None, bool]:
    """Map an SDK exception to (status, retry_after, is_network_error)."""
    if isinstance(exc, genai_errors.APIError):

def to_provider_error(provider: str, exc: Exception) -> ProviderError:
    """Classify any exception from a provider call as retryable or fatal."""
    if isinstance(exc, ProviderError):
        return exc

TimeoutError is in the network list on purpose. A provider that hangs is as useless as one that's down, and the next section turns a hang into a TimeoutError.

6. Three Providers, One Interface
This is the provider abstraction. Every provider gets the same method: await
provider.complete(messages) returns a string or raises ProviderError. The messages always come in one shape,
the OpenAI-style list most of the ecosystem already uses:
[{"role": "system", "content": "..."}, {"role": "user", "content": "..."}]

The base class does three jobs once, so the subclasses don't repeat them. It puts a timeout on every call,
it runs the chaos hook you'll build in section 10, and it translates every exception through to_provider_error.
Each subclass writes only _call_, the one SDK call.

7. Retry With Backoff
A 429 or a 503 often clears up in a second or two. So before giving up on a provider, try it again. The
question is how long to wait between tries.
Waiting a fixed second is the naive answer, and it breaks under load. If a thousand clients all hit a 429 at
the same moment, a fixed wait sends a thousand retries at the same moment too. Exponential
backoff doubles the wait each time (0.5 s, 1 s, 2 s). Full jitter picks a random wait between zero and that
number, which spreads the retries out.
There's one exception: if the server says how long to wait, believe it. Unless it says something like 41
seconds. A customer won't wait 41 seconds, and you have two other providers. So any server-requested
wait longer than cap means "give up and fail over now".
Save as src/resilience.py:

def backoff_delay(attempt: int, base: float, cap: float,
retry_after: float | None = None) -> float | None:
    """Seconds to wait before retry number `attempt` (0-based), or None = give u
p.
    
If the server said how long to wait, believe it - unless that is longer than
`cap`, in which case waiting is worse than failing over. Otherwise use
exponential backoff with full jitter: a random wait between 0 and base * 2^
n,
so many clients that failed together do not all retry together.
"""
if retry_after is not None:
    return retry_after if retry_after <= cap else None
return random.uniform(0, min(cap, base * 2**attempt))

A circuit breaker remembers. It has three states:  
- closed: calls go through as normal. After `threshold` failures in a row, it opens.  
- open: calls get skipped instantly. Nobody waits, and nothing gets sent to a provider that's down.  
  After `cooldown_s`, the next call goes through as a probe, and the breaker is half-open.  
- half-open: that one probe decides. Success closes the breaker; failure opens it again for another cooldown.  

The name comes from the electrical breaker in your fuse box: it trips so the fault doesn't keep damaging everything downstream. Add this to the bottom of `src/resilience.py`:  

class CircuitBreaker:  
    """Stops calling a provider that keeps failing, then tests it again later.  
    closed -> calls go through. `threshold` failures in a row -> open.  
    open -> calls are skipped instantly, no time wasted. After `cooldown_s`  
      the next caller gets through as a probe -> half_open.  
    half_open -> the probe decides: success -> closed, failure -> open again.  
    """  

def __init__(self, threshold: int, cooldown_s: float,  
              clock: Callable[[], float] = time.monotonic) -> None:  
    self.threshold = threshold  
    self.cooldown_s = cooldown_s  
    self.clock = clock  # injectable, so the self-test can fast-forward time  
    self.state = "closed"  
    self.failures = 0

Note what counts as one failure: one call that failed after all its retries, not each attempt. A blip that one retry fixes never touches the breaker. That's the split between the two tools: retries handle blips, the breaker handles outages.

9. The Router
The router is the one interface the agent sees. It owns a breaker per provider and walks the providers in order. For each one: skip it if its breaker is open, otherwise try it with retries. On success, record it and return. On failure, record it and move on.
complete() never raises. If every provider fails, it returns a degraded Reply with a safe holding message.
That's graceful degradation: the customer gets something honest, and the ticket gets flagged for a human.
Nobody gets a stack trace.

def _parse_steps(spec: str) -> set[int] | None:
    """'3-4' -> {3, 4}; '5' -> {5}; '' -> None, meaning every ticket."""
    if not spec:
        return None
    low, _, high = spec.partition("-")
    return set(range(int(low), int(high or low) + 1))

class ChaosPlan:
    """Which providers fail, and on which tickets."""

    def __init__(self, kill: str = "", flaky: str = "") -> None:
        self.down: dict[str, set[int] | None] = {}
        for part in filter(None, kill.split(",")):
            name, _, steps = part.partition("@")
            self.down[name] = _parse_steps(steps)
        self.flaky = set(filter(None, flaky.split(",")))
        self.step = 0

    def begin_ticket(self, step: int) -> None:
        """Called by the agent loop before each ticket."""
        self.step = step

    def inject(self, provider: str) -> None:
        """Raise a fake outage for `provider` if the plan says so; else do nothi
ng."""

        if provider in self.flaky:
            self.flaky.discard(provider)  # fail exactly once, then behave
            raise _sdk_error(provider, 503)
        if provider in self.down:
            steps = self.down[provider]
            if steps is None or self.step in steps:
                raise _sdk_error(provider, 429 if provider != "ollama" else 0)

    def attach(self, providers: list[Provider]) -> None:
        """Install the hook on every provider."""
        for provider in providers:
            provider.chaos = self.inject

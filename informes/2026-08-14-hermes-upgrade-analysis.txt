--- 5. PRECAUCIONES ---

1. Backup pre-update: config.yaml tiene updates.pre_update_backup: true
   (verificado) → hermes update genera backup automático. Además, copia
   manual de ~/.hermes/config.yaml antes (RULE-008).
2. Verificar tras el update, en orden:
   - hermes --version (debe decir v0.20.1)
   - grep _config_version ~/.hermes/config.yaml (debe decir 34)
   - telegram/slack/discord/platforms siguen en config (bug #62723)
   - hermes gateway / bot de Telegram responde
   - hermes tools list (toolsets intactos) y config show model.provider
     (deepseek-v4-flash)
3. Node 22.22.1 cumple (>=22.22.0). Verificar npm --version contra el
   rango del package.json antes del update.
4. Los +3 carried commits locales se pueden perder o entrar en conflicto
   con el update: revisar git status en ~/.hermes/hermes-agent antes.

--- 6. RECOMENDACIÓN ---

Decisión en una frase: ACTUALIZAR a 0.20.1 es viable y coincide con el
plan (era el objetivo de espera), sin urgencia, y con 3 pasos previos:
verificar npm/node, decidir el método (hermes update a main vs checkout
del tag v2026.8.13), y backup manual del config antes de ejecutar.

Matices:
- No hay urgencia: ninguna feature del rollup resuelve un problema actual
  del lab (A2A no se usa; el resto es estabilización). 0.17.0 funciona.
- El plan "esperar a la .1" se cumple: 0.20.1 existe y es estable.
- Riesgo principal: salto de config v30→v34 (4 migraciones acumuladas).
  Mitigado por pre_update_backup: true + bug de migración corregido +
  verificación post-update en orden (paso 5.2).
- La actualización NO se ejecuta sin confirmación explícita del usuario
  y sin el plan de verificación aprobado.
